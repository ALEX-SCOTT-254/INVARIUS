
# Security Policy

## Reporting a Vulnerability

Please do not disclose suspected security vulnerabilities, credentials,
private keys, or other sensitive information in public GitHub issues.

INVARIUS is under active development. A dedicated security response
process and guaranteed response times have not yet been established.

Until a dedicated private reporting channel is published, contact the
repository maintainer privately through an appropriate contact method
listed on the maintainer's GitHub profile. Do not include secrets or
sensitive user data in an initial message.

When reporting a suspected vulnerability, provide only the information
needed to explain the issue, such as:

- A concise description of the suspected vulnerability.
- The affected repository component or version, if known.
- Steps to reproduce the issue in a safe, authorized environment.
- The potential impact and any relevant limitations or assumptions.

Do not access, modify, or extract data belonging to others, disrupt
services, or test systems without authorization.

## Scope and Current Status

INVARIUS is an actively developed project. Security controls and
verification coverage are evolving, and the presence of security-related
architecture or documentation does not guarantee that every control
has been implemented or independently assessed.

Please distinguish confirmed vulnerabilities from hypotheses, and
include supporting evidence where it is safe to do so.

## Response Expectations

There is currently no published service-level agreement for security
reports. Reports will need to be assessed based on the available
information, project status, severity, and maintainer capacity.
